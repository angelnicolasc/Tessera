# ADR-0004 — `CompressionScheme` is `#[non_exhaustive]` from day one

**Status:** Accepted 2026-05-21. **Partially superseded** by
[ADR-0020](0020-v4-hybrid-attention.md) (2026-05-28): the `DsaHierarchical` placeholder
this ADR introduced was replaced by three sibling variants (`V4Csa`, `V4Hca`, `V4Swa`)
when the DeepSeek-V4 paper made the real architecture public. The `#[non_exhaustive]`
foundation this ADR established remains in force and is what made the V4 migration
strictly additive. Retained as the historical record of the design pattern.

## Context

DeepSeek-V4 introduces DSA (Deep Sparse Attention) with two compression tiers (`c4a` /
`c128a`) plus a sliding-window region. Block sizing, eviction heuristics, and kernel
dispatch all depend on which tier a block belongs to. We do not have the V4 spec public
enough to implement DSA today, but the Tessera codebase must accept the variant **now** so
that Sprint 1 lands DSA without breaking-change refactors.

Two failed alternatives:

* **Add a `scheme: String` field.** Stringly typed; `cargo build` doesn't help us find sites
  that need updating; consumers can ship invalid configs that crash at runtime.
* **Wait until V4 is public.** Forces a breaking-change refactor when it lands. Every match
  arm in the codebase is a manual audit item.

## Decision

```rust
#[non_exhaustive]
pub enum CompressionScheme {
    MlaLatent { latent_dim: u32, rope_key_dim: u32 },
    DsaHierarchical { coarse_dim: u32, fine_dim: u32, swa_window: u32 },
    MhaFull { num_heads: u32, head_dim: u32 },
}
```

* `MlaLatent` is fully implemented in Sprint 0.
* `MhaFull` is implemented as a degraded fallback for non-MLA models.
* `DsaHierarchical` is accepted by the type system; every `match` site returns
  `unimplemented!("DSA block sizing TBD — see docs/src/adr/0004-compression-scheme-enum.md.")`.

`MlaBlockConfig::new` rejects DSA configs with `TesseraError::InvalidConfig` to keep
production behaviour clear.

## Consequences

* When the V4 spec lands, `cargo build` enumerates every site that needs DSA logic — the
  refactor becomes a worklist generated by the compiler, not a manual audit.
* `#[non_exhaustive]` propagates to downstream Rust users: they MUST handle the wildcard arm
  in their own `match` blocks. This is intentional and the public-API expectation.
* The Python `_native` module exposes `CompressionScheme.dsa_hierarchical` so wiring against
  the API can begin before the kernel lands.
